# Feature Specification: Code Explanation & Developer Learning

**Module ID:** `SPEC-05-LEARN`  
**Package:** `@ctrlplane/explanation`  
**Status:** Ready for Review

---

## 1. Objective & Scope

The Code Explanation & Developer Learning module helps developers rapidly understand, critique, and audit code generated by AI coding agents.

Rather than generating generic code summaries or attempting to guess an LLM's unobservable internal chain of thought, this module focuses strictly on **observable deltas and risk surfaces**:
1. **Blast Radius Analysis:** Which downstream files, modules, or exports are affected by this change?
2. **Dependency & Security Audit:** Did the agent add new third-party libraries, new external network endpoints, or change security configurations?
3. **Architectural Invariants:** Were core project patterns (e.g., error handling conventions, immutability, transaction boundaries) respected?
4. **Socratic Comprehension Quizzing:** Optional interactive checks to test whether the developer understands subtle edge cases before merging.

## 3. Functional Requirements

### 3.1 Delta-Focused Diff Analysis
When triggered via CLI (`ctrlplane explain`) or session completion:
1. **AST Diff Breakdown:** Parses the Git diff into structural components (functions modified, types altered, new exports, deleted logic).
2. **Blast Radius Computation:** Scans the codebase to determine all call sites referencing the modified symbols.
3. **Dependency Drift Detection:** Inspects `package.json`, `requirements.txt`, `go.mod`, or `Cargo.toml` in the diff:
   * Flags newly introduced external dependencies.
   * Warns if a dependency has known CVEs or poor maintenance indicators.
4. **Risk Scoring:** Computes an automated risk score (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`) based on:
   * Modification of auth/crypto/billing code.
   * Number of files touched ($> 10$ files = elevated risk).
   * Ratio of test lines to implementation lines.

### 3.2 Socratic Interactive Comprehension ("Grill Me" Mode)
To combat rubber-stamp approvals, developers can run:
```bash
ctrlplane explain --quiz
```
* Generates 2 targeted multiple-choice or short-answer questions focused on the most complex or dangerous part of the changeset (e.g. *"What happens if the token expires during a concurrent database transaction on line 42?"*).
* Helps the developer verify that they truly comprehend the code before approving or pushing.

### 3.3 Output Format
```
================================================================================
                      CTRLPLANE DELTA EXPLANATION
================================================================================
Change Summary: 4 files changed (+124, -18)
Risk Level:     MEDIUM (Touches authentication and session cookies)

1. STRUCTURAL CHANGES & BLAST RADIUS
  • src/services/auth.ts: Added rotateRefreshToken()
    → Blast Radius: Called by src/routes/auth.ts (POST /api/auth/refresh)
  • src/types/auth.ts: Updated UserSession interface with 'refreshTokenHash'

2. DEPENDENCY & SECURITY AUDIT
  • New Packages: None added. (Safe)

    Recommendation: Add a test case asserting concurrent refresh behavior.
================================================================================
```

## 4. Data Models & TypeScript Schemas

```typescript
import { z } from "zod";

export const RiskLevelSchema = z.enum(["LOW", "MEDIUM", "HIGH", "CRITICAL"]);

export const SymbolBlastRadiusSchema = z.object({
  symbolName: z.string(),
  filePath: z.string(),
  referencesCount: z.number().int(),
  referencingFiles: z.array(z.string()),
});

export const DependencyDeltaSchema = z.object({
  packageName: z.string(),
  version: z.string(),
  isDev: z.boolean(),
  status: z.enum(["added", "updated", "removed"]),
  license: z.string().optional(),
});

export const ComprehensionQuestionSchema = z.object({
  id: z.string(),
  questionText: z.string(),
  options: z.array(z.string()),
  correctOptionIndex: z.number().int(),
  explanation: z.string(),
});

export const ExplanationReportSchema = z.object({
  sessionId: z.string(),
  gitCommitSha: z.string(),
  riskLevel: RiskLevelSchema,
  summary: z.string(),
  blastRadius: z.array(SymbolBlastRadiusSchema),
  dependencyChanges: z.array(DependencyDeltaSchema),
  potentialRisks: z.array(z.string()),
  comprehensionQuestions: z.array(ComprehensionQuestionSchema).optional(),
  generatedAt: z.number().int(),
});

export type ExplanationReport = z.infer<typeof ExplanationReportSchema>;
```

## 5. Failure Modes & Edge Cases

1. **Large Changesets (> 5,000 LOC):** If an agent generates an enormous diff, full AST blast radius computation could become sluggish. The module chunks files by priority (production code first, test files second, generated files ignored) and caps analysis at 50 files.
2. **Missing Local Model or API Key:** If no LLM is configured for explanations, the module falls back to pure static analysis: AST blast radius, file counts, and dependency diffs are computed deterministically without AI prose.

## 6. Acceptance Criteria

- [ ] **AC-LEARN-1:** Delta explanation identifies all modified functions and their external referencing call sites in the project.
- [ ] **AC-LEARN-2:** Any added third-party package in `package.json` or equivalent manifest is flagged in the dependency audit section.
- [ ] **AC-LEARN-3:** The explanation report avoids claims about internal agent thoughts and grounds statements in concrete code lines.
- [ ] **AC-LEARN-4:** Running `ctrlplane explain --quiz` generates testable comprehension questions derived from the active diff.
